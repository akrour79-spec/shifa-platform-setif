# 🏥 منصة شِـفَـاء - ولاية سطيف | Shifa Healthcare Platform

منصة رقمية لحجز المواعيد الطبية وإدارة العيادات في ولاية **سطيف - الجزائر**،
مع قاعة انتظار حية تعمل على شاشات العرض داخل العيادة.

الحالة الحالية: **تطبيق كامل-stack يعمل فعلياً** — أطباء حقيقيون يسجّلون عياداتهم
ويجدون طلبات حقيقية. البيانات الموجودة الآن تجريبية، وكلها **موسومة صراحةً**
بشارة "بيانات تجريبية" على كل عيادة وبإعلان في أعلى الدليل.

---

## 🌟 ما الذي يعمل الآن

| الميزة | المصدر |
|---|---|
| دليل الأطباء والعيادات + فلترة بالبلدية/التخصص/البحث | `GET /api/doctors` → Postgres |
| قوائم الفلترة (البلديات والتخصصات) | `GET /api/doctors/meta` → Postgres |
| الخانات المتاحة بالتاريخ المحدَّد | `GET /api/doctors/:id/availability` |
| الحجز ومنع الحجز المزدوج وترقيم الدور | `POST /api/appointments` (معاملة + فهرس فريد) |
| تسجيل طبيب مع إنشاء عيادته | `POST /api/auth/signup` |
| تسجيل الدخول (هاتف + كلمة سر، bcrypt + JWT) | `POST /api/auth/login` |
| قراءة الملف الشخصي وحالة العيادة | `GET /api/auth/me` |
| تعديل الملف الشخصي (الاسم والبلدية) | `PATCH /api/auth/me` |
| تغيير كلمة السر | `POST /api/auth/change-password` |
| طابور العيادة الحيّ + استدعاء + إنهاء معاينة | `GET/POST /api/queue/*` |
| شاشة العرض لقاعة الانتظار (تحدّث نفسها) | `GET /api/queue/screen` |
| ملف العيادة (يظهر للمرضى مباشرة) | `PUT /api/doctors/me` |
| خريطة تفاعلية (Leaflet) | إحداثيات من القاعدة |

**ما ليس موجوداً بعد**: الدفع الإلكتروني. نموذج الاشتراكات صفحة تسويقية
تعرض الخطط فقط ولا تُحصَّل ولا تُدفع — اقرأ [docs/BUSINESS_MODEL.md](docs/BUSINESS_MODEL.md).
ولا توجد إشعارات SMS ولا Supabase Realtime: الطابور يتحدّث بـ polling
كل 15 ثانية، وتذكير واتساب رابط يفتحه المستخدم بنفسه.

## 🩺 تسجيل الأطباء واعتماد العيادات

لا يُعتمد أي طبيب بمجرد التسجيل — حتى لا تظهر عيادة غير حقيقية بين أيدي المرضى.

```
طبيب يسجّل  →  عيادته تُنشأ is_active = FALSE  →  لا تظهر في الدليل
                                          ↓
                              الإدارة تراجع العيادة
                                          ↓
                       node server/db/approve-clinic.js <الهاتف> --yes
                                          ↓
                            is_active = TRUE  →  تظهر وتقبل حجوزات
```

هذا مقصود: التسجيل مفتوح للجميع، والاعتماد يدوي. عيادة غير مُتحقَّق منها في
دليل طبي عام ضررٌ مباشر على المرضى.

### أوامر الاعتماد

```bash
# عرض كل العيادات بحالتها (تُدرج التجريبية بوسم [تجريبية])
node server/db/approve-clinic.js list

# تفعيل عيادة برقم هاتفها (نقّال أو ثابت)
node server/db/approve-clinic.js 0661122399 --yes

# مع ضبط الإحداثيات والسعر والدوام
node server/db/approve-clinic.js 0661122399 \
  --lat 36.1892 --lng 5.4128 --price 2000 \
  --hours "08:00 - 16:30" --days "0,1,2,3,4,6" --yes

# أو عبر npm
npm run approve-clinic -- list
```

بلا `--yes` تطلب الأداة تأكيداً على الطرفية، وبلا طرفية تفاعلية **ترفض التنفيذ**
ولا تغيّر شيئاً. هذا يمنع إعلان عيادة بالخطأ من خطّأ آلي.

> **مهم**: الإحداثيات الافتراضية هي مركز مدينة سطيف (36.1898, 5.4108).
> إن تُركت، ستظهر العيادة في مكان خاطئ على الخريطة. اضبطها عند الاعتماد.

### ما يراه الطبيب المعلَّق

لافتة واضحة في أعلى لوحته تقول إن عيادته بانتظار المراجعة ولم تظهر بعد للمرضى.
قبل هذا كانت لوحة فارغة بلا تفسير، فيظن الطبيب أن عيادته معطّلة.
الواجهة تقرأ الحالة من الخادم عند كل إقلاع — لا من التخزين المحلي — لأن
الاعتماد يحدث من الطرف الآخر.

## 🏷️ وسم البيانات التجريبية

العمود `doctors.is_demo` يميّز البيانات الوهمية عن الحقيقية:

- كل عيادة تجريبية تحمل شارة **"بيانات تجريبية"** على بطاقتها
- يظهر إعلان في أعلى الدليل بعدد العيادات التجريبية
- إن كانت كل العيادات تجريبية، يغيّر الإعلان صيغته ليقول ذلك صراحةً

هذا ليس زينة: عيادات سطيف في هذا الدليل **مُختلقة**. عرضها بلا وسم يعني
أن نكذب على مريض يظنّ أنه يحجز عند طبيب حقيقي.

قبل العرض النهائي: احذف العيادات الثماني ومواعيدها التجريبية من القاعدة.

## 🔐 النموذج الأمني

هذه ليست قائمة تحقق، بل قرارات تصميم:

**المتصفح لا يتصل بقاعدة البيانات إطلاقاً.** Express هو طبقة الـ API
وطبقة الصلاحيات الوحيدة. Supabase anon/authenticated ممنوعة من كل الجداول
عبر `SUPABASE_LOCKDOWN.sql`. المتصفح لا يعرف عنوان قاعدة البيانات ولا كلمة
مرورها ولا حتى اسم `anon`.

**الدفع غير موجود عمداً.** لا نجمع رقم بطاقة ولا CVV. أي بوابة دفع ستُدمج
عبر حساب مُنشأ لدى مزوّد خارجي (Chargily) حيث لا تمر بيانات البطاقة بخوادمنا.

**الحالات تُخزَّن بالإنجليزية وتُترجَم عند العرض.** القاعدة تقرأ
`confirmed`، الواجهة تعرض `مؤكد`. الترجمة في `server/lib/constants.js`
و`api.normalizeAppointment()` — تغييرها لا يمسّ البيانات.

**كل نص من القاعدة يمرّ عبر `api.escape()` قبل `innerHTML`.**
الهجوم المخزَّن عبر اسم طبيب أو مريض لا ينفّذ في متصفح الطبيب.

**لا يوجد `onclick=` مضمّن في أي مكان.** سياسة `Content-Security-Policy`
في `server/index.js` تضع `script-src-attr 'none'`، وهو ما يُبطل كل معالجات
سمات HTML بصمت. الأزرار تحمل `data-ui="اسم"` ويفوّضها `initUiDelegation()`
عبر قائمة بيضاء. هذا لا يقلّل الأمان فقط، بل يُغلق مسار XSS عبر السمات
ويمنع النماذج من الإرسال الافتراضي الذي يمسح بيانات المريض.

**تفاصيل الثغرات المُصلَحة**: [docs/CHANGELOG_SECURITY.md](docs/CHANGELOG_SECURITY.md)

## 📌 دروس من حوادث فعلية

هذه ليست قواعد نظرية — كل بند منها يلتقط حادثة حدثت فعلاً في هذه القاعدة.

**ترحيل لا يُسقط جدولاً غير فارغ أبداً.** `000_drop_legacy.sql` كان
`DROP TABLE IF EXISTS appointments` صِرفاً. حدث أن كانت جداول التطبيق موجودة
بينما `_migrations` كان فارغاً، فظنّ `npm run migrate` أن كل الترحيلات جديدة
ونفّذ 000 على قاعدة فيها بيانات — وضاع كل جدول المواعيد. صار الملف
plpgsql مشروطاً، وأُضيف `assertNoOrphanSchema()` في `migrate.js` يرفض العمل
على قاعدة بلا سجل ترحيلات. **لا تُضعف هذين الحاجزين.**

**دالة معرَّفة مرتين تبتلع الأولى بصمت.** كان في `app.js` نسختان من
`showToast`: الأولى كاملة (تهريب + أنواع + وعاء موحّد)، والثانية أبسطها
(صندوق يُلحق بـ `document.body` ويتجاهل النوع). الثانية هي التي كانت تعمل،
فكل رسائل الخطأ والتأكيد كانت تظهر بلا تمييز. `node --check` لا يلتقطها
والمتصفح لا يشتكي: الزر يعمل والرسالة تظهر. فحص بنيوي يمنعها الآن.

**رسالة تحذير بألوان النجاح.** `showToast` افتراضيها `success` أخضر بعلامة
صح. رسالة تحذير بعلامة ⚠️ كانت تظهر خضراء — وهذا أسوأ من غيابها.
كل استدعاء يحمل ⚠️ يجب أن يصرّح بنوعه، وهناك فحص يبقي ذلك.

**فقد حالة العيادة عند تسجيل الدخول كان يخفي شيئاً حقيقياً.** `setSession`
كان يخزّن المستخدم فقط، و`/api/auth/login` لم يكن يُرجع العيادة إطلاقاً
(على خلاف `/api/auth/me`). فكان الطبيب المعلَّق يدخل لوحة فارغة بلا تفسير.
الآن الحالة تُرفق في المسارين وتُقرأ من الخادم عند كل إقلاع.

**رقم الهاتف الثابت كان مرفوضاً رغم أن تعليق الملف يزعم قبوله.** النص
يقبل الثابت، والكود يرفضه. أي أن نصف أرقام دليل الأطباء الإعلاني — وكلها
أرقام ثابتة — كان غير قابل للتسجيل أصلاً. التعليقات التي تصف ما يفعله
الكود يجب أن تُختبر، لا أن تُقرأ.
